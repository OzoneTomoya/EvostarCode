# Merge Quant (Mistral Models, Multi-Objective Optimization)

Experiments on multi-objective optimization with Mistral models.

## Environment Setup
1. Create a virtual environment
```
python -m venv [envname]
```

2. Activate the virtual environment
```
source [envname]/bin/activate
```

3. Install the required libraries
```
pip install -r requirements.txt
```

4. Download the language identification model lid.176.ftz from [the link](https://fasttext.cc/docs/en/language-identification.html)
```
wget https://dl.fbaipublicfiles.com/fasttext/supervised-models/lid.176.ftz
```

5. (Optional) Log in to Hugging Face

Some gated or restricted models may require requesting access on Hugging Face before downloading.

```
huggingface-cli login
```

## Running the Experiment
1. Run the script
```
bash ./optimization.sh
```

## optimization.sh
The following example is intended for a quick functionality check.
For full experiments, increase `--num-trials`.
```
python main.py \
    --optimization Sequential_BitWidth \
    --num-trials 5 \
    --seed-opt 0 \
    --seed-merge 0 \
    --wandb False \
    --wandb-project 'MergeQuant' \
    --result-dir 'results' \
    --figure-dir 'figures' \
    --test-best True \
    --create-graph True \
```
- optimization: Optimization strategy
    - Sequential_BitWidth: Optimizes quantization bit-widths
        - To run this, the file ./config/best_config_seed{args.seed-opt}.yml is required. This file is generated by running `Sequential_MergeParameter` in `Mistral/Constrained_Optimization`. It must be copied manually to the `./config/` directory.
    - Joint: Optimizes merge parameters and quantization bit-widths
- num-trials: Number of Optuna trials
- seed-opt: Random seed for the sampler
- seed-merge: Random seed for model merging
- wandb: Enable logging with Weights & Biases (optional) (`True` or `False`)
- wandb-project: Project name used when logging experiments with Weights & Biases (W&B)
- result-dir: Directory to save results
- figure-dir: Directory to save figures
- test-best: Evaluate the best configuration on the test set
- create-graph: Generate Pareto front plots

## Experimental Results

The raw experimental results and optimization logs are stored in the `result/` directory. Results are organized by optimization strategy.

For clarity and reproducibility, this repository stores experimental results in a more organized format than the original implementation.
As a result, some saved files may differ slightly from those used during the original experiments.

### Directory Structure
```
result/
├── Joint/
│   └── seed=0/
│       ├── results_seed=0/
│       └── figure_seed=0/
│   
└── Sequential_BitWidth/
    └── seed=0/
        ├── results_seed=0/
        └── figure_seed=0/
    
```

- `results`
    ```
    results/
    ├── pareto.json               # Non-dominated solution set obtained through optimization
    ├── pareto_fronts.csv         # Non-dominated solutions in CSV format
    ├── study_trials.csv          # Optimization history
    ├── trial_{num}.json          # Model outputs saved at each evaluation step during optimization
    ├── ...
    ├── test_result_{number}.json # Test outputs from evaluating the non-dominated solutions on the test data
    ├── ...
    ├── test_score_{number}.json  # Evaluation scores from evaluating the non-dominated solutions on the test data
    └── ...
    ```

- `figures`
    ```
    figures/
    └── pareto_fronts.png    # Visualization of Pareto front
    ```
